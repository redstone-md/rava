**rava v0.0.4-alpha: correctness fixes for calls, the collector and JNI.**

`alpha` · Linux, macOS and Windows on x86-64 · Java 21 class library · drop-in `java`

> [!WARNING]
> An alpha: expect crashes and differences from HotSpot, and keep backups of any world you open
> with it. Reports are welcome in [Issues](https://github.com/redstone-md/rava/issues).

## 🐛 Fixes

- **Negative int arguments across calls.** Optimized code passing an `int` argument in a register
  to a method still running in baseline code sent the raw 64-bit register, so a negative value
  arrived as a large positive one (`sink(x - 1)` returned `4294967295` for `x = 0`). Sizes and
  loop bounds computed from such calls went wrong, which could hang the game or crash a native
  library. Int arguments are now sign-extended at the boundary.
- **A collector could scan an exiting thread's freed frames.** A thread leaving published itself
  as native before leaving the registry, so a collection in between could scan its stack after
  it was freed. It now leaves the registry while still counted as running.
- **JNI string getters** (`GetStringChars`, `GetStringUTFChars`, lengths, regions) read the
  string inside the VM now, so a young collection cannot move the backing array under them.
- **`SetObjectArrayElement`** raises `ArrayStoreException` on a type mismatch, as the bytecode does.
- Optimized compilation no longer bails out on a folded constant in a fast exit, on a static
  method with no locals entered through OSR, or leaves a trampoline aimed at retired code.
- Fault reports print once (Unix), and `RAVA_OPT_EXCLUDE` now also covers loops compiled from a
  running frame, so crash bisection is reliable.
