**The first public build of rava: a Java Virtual Machine written from scratch in Rust.**

`alpha` · Linux, macOS and Windows on x86-64 · Java 21 class library · drop-in `java`

> [!WARNING]
> An alpha. It runs real servers and the Minecraft client, but it is young: expect crashes and
> differences from HotSpot, and keep backups of any world you open with it. Reports are welcome
> in [Issues](https://github.com/redstone-md/rava/issues).

## 🚀 Highlights

- **Drop-in `java`.** Wherever you would type `java`, type `rava`: the same command line,
  output, error messages and exit codes. `-jar`, `-cp` with wildcards, modules, single source
  files, `@argfiles`, `-D`/`-X`/`-XX` options and the `JAVA_*_OPTIONS` variables.
- **Self-contained.** The archive carries the Java class library rava runs; the JDK's native
  methods are implemented in Rust, so there is nothing else to install.
- **Two-tier JIT.** A baseline x86-64 compiler for everything warm, an SSA optimizing tier for
  what is hot: inlining, type profiles and inline caches, class hierarchy analysis,
  speculation with deoptimization, on-stack replacement, loop-invariant code motion.
- **Generational collector** with compressed references and a 32-bit class word; parallel
  marking.
- **JNI.** Native libraries load and run as on HotSpot, at HotSpot's call cost (10-13 ns a
  call): netty's epoll transport on servers, LWJGL on the client.
- **Three systems.** One VM for Linux, macOS and Windows on x86-64, each built and checked
  against HotSpot in CI; Apple Silicon Macs run the macOS build through Rosetta 2.
- **Thread dumps** on `kill -3`, `Ctrl+Break`, or every N seconds with `RAVA_DUMP_EVERY`, for
  diagnosing hangs ([troubleshooting](https://github.com/redstone-md/rava/blob/main/docs/troubleshooting.md)).
- **No snapshots, no workload tuning.** Every start is cold from class files: no CDS-like
  archive, checkpoint or AOT cache, and nothing in the VM is keyed to a particular program.

## 🎮 What runs

| | |
|---|---|
| Paper 1.21.1 | starts and serves, native epoll transport |
| NeoForge 1.21.1 server, All The Mods 10 | starts and ticks |
| Minecraft 1.21.1 client | vanilla, Fabric (with Sodium and Fabric API) and NeoForge, into a singleplayer world; from Prism Launcher on Windows ([how](https://github.com/redstone-md/rava/blob/main/docs/minecraft.md)) |

## 📊 Numbers

Against HotSpot (JDK 21) on the same 4-vCPU Xeon:

| | rava | HotSpot |
|---|---:|---:|
| Paper 1.21.1, cold start to `Done` | 34.4 s | 28.5 s |
| Hello world | 92 ms | 54 ms (72 ms without its class-data archive) |
| ATM10 server, resident memory after two tick sprints | 7.3 GB | 8.2 GB |
| JNI call, `static int add(int, int)` | 10-13 ns | 12-15 ns |

## ⚠️ Known limitations

- x86-64 only (Linux with glibc 2.35 or newer, macOS, Windows 10 or newer); no native ARM
  build yet.
- On Windows, native calls take the generic path (slower than on Linux), `ProcessHandle.Info`
  is empty, and AWT is not available.
- The bundled class library is Java 21's, so programs that need Java 25 (Minecraft 26.x) do
  not run yet; a JDK 25 class library works from a source build. Java 8 programs (Minecraft
  1.12.2 with LaunchWrapper) do not run.
- No JVM TI: `-javaagent` and `-agentlib` are refused.
- `NullPointerException` messages are the classic ones, not HotSpot's helpful texts.
- HotSpot is still ahead on start-up time and on peak speed in the server tick.
