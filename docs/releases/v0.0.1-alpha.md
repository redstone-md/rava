**rava v0.0.1-alpha: the first alpha of a Java virtual machine written from scratch in Rust.**

`alpha` · Linux, macOS and Windows on x86-64 · Java 21 class library · drop-in `java`

> [!WARNING]
> An alpha: expect crashes and differences from HotSpot, and keep backups of any world you open
> with it. Reports are welcome in [Issues](https://github.com/redstone-md/rava/issues).

rava runs Java programs the way `java` does: same command line, same output, same exceptions,
same exit codes. Each archive carries its own copy of the Java class library, and rava
implements every native method itself, so you do not need to install anything else. It starts
a Paper 1.21 server and runs the Minecraft client, vanilla and modded, from the usual
launchers. Every start is cold. There is no class-data archive, no checkpoint/restore, no AOT
cache, and nothing is tuned for a particular program.

## What is in it

- A two-tier JIT to x86-64.
  - The baseline compiler emits machine code straight from bytecode.
  - The SSA optimizing tier inlines by type profile and class hierarchy analysis. It speculates
    with deoptimization, scalar-replaces allocations that do not escape, numbers loads, and
    removes redundant checks.
  - Running loops enter optimized code by on-stack replacement.
- A generational garbage collector with bump allocation inline in compiled code, parallel
  marking, compressed references and a 32-bit class word.
- Real JNI. Native libraries such as netty's epoll, LWJGL and OpenAL load and run as they do on
  HotSpot, at HotSpot's call cost.
- The `java` command line, unchanged: `-jar`, `-cp`, modules, single source files, `@argfiles`,
  `-D`/`-X`/`-XX`, thread dumps on `Ctrl+Break` / `kill -3`.
- Diagnostics: `RAVA_SAMPLE` (a sampling profiler), `RAVA_MEM_LOG`, `RAVA_TRACE_JNI`, perf
  maps of compiled code, and crash reports.

## Performance

Steady-state microbenchmarks against HotSpot (OpenJDK 21.0.7, Microsoft build) on an
i5-14400F, with both pinned to the performance cores. Each figure is the best of interleaved
rounds, rava's time divided by HotSpot's. Below 1, rava is faster.

| Benchmark | What it runs | rava / HotSpot |
|---|---|---:|
| TextBench | Minecraft's formatted-text walk (`StringDecomposer`) | **0.74** |
| ParticleBench | billboard particle quads written to off-heap vertex buffers | **0.90** |
| CubicBench | Minecraft's sky and fog colour sampling (`CubicSampler`) | **1.00** |
| JomlBench | entity-part transforms with JOML (pose stack, quaternions) | **1.00** |
| FormatBench | `String.format` with ints, doubles and strings | 1.14 |
| RegexBench | `java.util.regex` matching | 1.24 |

In the Minecraft client, frame rate on a frozen scene is about 0.9× HotSpot's.

The cause of the slower rows is known. The optimizing tier allocates values to 9 general
registers where C2 has about 13, so formatting and regex code with many live values spills
more. Fixing that is the next large piece of work.

## Known limits

- x86-64 only, and the Java 21 class library only.
- rava does not produce helpful `NullPointerException` messages yet.
- Some programs will crash or behave differently from HotSpot. Please report them with
  `rava -version`, the system, the command line and the full output.
